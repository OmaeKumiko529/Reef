# 1.0 总纲

暗礁是一款结合了历史与政治元素的策略游戏。在游戏中，玩家要扮演**情报机构**的一名主管，通过获得的**情报**进行渗透与控制，最终见证国家与世界的走向。

# 2.0 游戏内容

## 2.1 游戏开始

游戏开始的标志性事件是冷战揭开帷幕。在这个世界里，法西斯主义政权与民主主义政权、社会主义政权分庭抗礼，随着热战逐渐平息，取而代之的是三极竞争的冷战时代。

**卢泰西亚国**是游戏的主要背景发生地。在游戏中，玩家将扮演卢泰西亚新任命的**情报主管**，以国家安全的名义，监控国内的社会动荡与政治运动，并用无形的大手为各式各样**意识形态**推波助澜，让卢泰西亚的人民推搡着进入下一个时代。而这一切，都由玩家随心而定。

### 2.1.1 势力

卢泰西亚国内存在着诸多**势力**，玩家可以选择帮助这些**势力**拓展**影响力**，触发各种各样的**事件**。

<callout emoji="🆑">
设计观点备注
以冷战为核心背景的政治游戏，其关键在于如何权衡本势力在国家中的渗透力。  
❌这意味着，势力获胜的首要条件就是让自身政治思潮的影响力尽可能覆盖全国。  
因此，应当设计一种以地块划分的影响力机制，计算地块中每个势力对其的影响力，进而触发事件与可用的行动。
</callout>

### 2.1.2 目标

玩家的目标是在众多剧情分支线上，找到一条能够称心如意的结局。这些结局由各种方面的因素决定走向。

### 2.1.3 时间推进

游戏时间以**日**为最小单位逐日推进，起始于 1945 年 9 月 2 日，默认推进速度为每秒 1 天（`daysPerSecond`，可在 `GameClock` 中调整）。

玩家按下空格键，或点击右上角时间面板的**暂停**与**开始**按钮，即可暂停或继续时间流逝。每日推进时，系统依次结算各系统的**逐日**效果（如**渗透**的**影响力**加成与衰减），并在日期满 31 日后进位到下一个月、满 12 个月后进位到下一年。当有**事件**被触发时，游戏会自动暂停，待玩家完成**事件**选项后再恢复推进。

<callout emoji="❓">
设计观点备注
`GameClock` 是时间系统的核心类，持有当前年、月、日，并通过 `OnDayPassed` 事件通知各系统结算每日逻辑。**事件**触发时调用 `PauseForEvent` 暂停推进，玩家选完选项后调用 `ResumeFromEvent` 恢复。该设定似乎需要讨论，并可能在以后进行更新修正。
</callout>

## 2.2 游戏中

### 2.2.1 地图

地图以若干**区块**划分，通常根据行政**省份**划分**区块**。

<callout emoji="💬">
设计观点备注
这是参考了史实策略游戏的内容。区块是玩家进行微操的基本单位。
</callout>

#### 2.2.1.1 区块的详细面板

在地图上单击某个**区块**，即可在侧栏打开该**区块**的详细面板。这个面板里将会注明以下信息：

1. **区块**对应的**省份**名（string）
2. 在当前**区块**上，玩家对其施加的**影响力**（float）
3. 该**区块**的**利益集团**占比（维护二维数组(string,float)或其他方法）
4. 该**区块**的**政治思潮**占比（维护二维数组(string,float)或其他方法）
5. **主要产出物**（维护一个string数组记录商品ID，如 grain（粮食）、coal（煤）、steel（钢））
6. 该**区块**的**主流文化**（string记录文化ID，如 culture_lutetian（卢泰西亚））
7. 该**区块**的**贸易线路**（维护一个string数组记录贸易线路ID，如 route_capital_port（首都港）；当前占位实现固定为默认线路，面板暂未展示）

### 2.2.2 机构

**机构**涵盖整个国家。

#### 2.2.2.1 政府

**政府**是表面上支持玩家的国家势力。**政府**为玩家提供**政府报告**，玩家也亦能反过来操纵**政府**。

##### 2.2.2.1.1 政府报告内容

对于每个**区块**和**国家**而言，**政府报告**包括如下内容：

| 类名（区块） | 数据类型 | 类名（国家） | 数据类型 |
|-|-|-|-|
| 利益集团占比 | 每个**利益集团**在该**区块**的力量占比 | 意识形态 | 国家官方的**意识形态** |
| 政治思潮占比 | 该**区块**的**政治思潮**及其力量占比 | 领导人 | **领导人**的详细数据 |
| 经济状况 | 该**区块**的**主要产出物**与**贸易线路** | 国际地位 | 国家在国际上的地位 |
| 文化状况 | 该**区块**的**主流文化** | 外交关系 | 国家的**外交关系** |

<callout emoji="💬">
设计观点备注
原型阶段暂时不考虑国家与国际关系。优先把单个国家的机制完善。
</callout>

###### 2.2.2.1.1.1 利益集团

**利益集团**是描述一个政治实体内，人群基于自身政治利益而划分的立场。一般情况下，**利益集团**如下：

| 利益集团 | ID | 描述 |
|-|-|-|
| 知识界 | knowledge | 学生、教师、知识分子等一切从事学术工作的人。 |
| 工商界 | industry | 掌握工厂、制造厂的资本家，或是资本公司的小老板。 |
| 政治界 | politics | 从事政治工作的官僚、竞选家、党派成员。 |
| 军队 | military | 在军队内服役的职业军官、士兵。 |
| 劳工界 | labor | 出卖劳动力或自身以赚取微薄工资的工人、农民与奴隶。 |

**利益集团**会影响该**区块**的**政治思潮**及其力量占比。因此，在关键的**区块**采取行动时，首先应该关注该地区的**利益集团**情况。

###### 2.2.2.1.1.2 政治思潮 ❓

**政治思潮**是描述游戏中人群所表达政治诉求的概括。一般情况下的**政治思潮**包含这些：

| 政治思潮 | ID | 描述 |
|-|-|-|
| 社会主义思潮 | socialism | 强调公平分配、消灭剥削的思潮 |
| 民主主义思潮 | democracy | 强调政治公平、过程正义的思潮 |
| 法西斯主义思潮 | fascism | 强调国家优先、扩军侵略的思潮 |

❌ 开局**利益集团**占比 `initialIGroups` 与开局**政治思潮**占比 `initialIdeologies` 为 `ProvinceData` 字段；`CreatePlaceholder` 现读取两字段并归一化为占比，未配置或权重全 0 时回退为按 1/N 平均分配。

<callout emoji="❓">
此处在实际代码中不再使用归一化为占比的方法，而是替换成零和比例转移的方法。具体操作是从所操作的其余思潮中按其当前占比扣除`delta`，不足部分`clamp`后二次归一。这一过程在数学上与等比缩放等价。
设`target`的当前值为t，其余思潮总和为：
$$R=1-t$$
此时`target`变为：
$$t + Δ$$
其余就会按照比例扣除`delta`。但是有一个极端条件，就是所操作的思潮为1，而其余思潮都为0。（`othersSum<=1e-6` 时 `each = (1-newTarget)/others.Count`）这时候就需要给其余所有思潮各分配：
$$-Δ/(n-1)$$
处理这一边界的方法为`ShiftShare`。
用数学语言描述上述零和比例转移：设某区块有`n`个政治思潮，占比分别为 $p_1, p_2, \dots, p_n$，满足 $\sum p_i = 1$（即 100%）。对目标思潮 k 施加增量 $\Delta$（可正可负），其余思潮统称“其他”。
**第 1 步：移动目标。**目标从 $t = p_k$ 变为 $t' = \text{clamp}(t + \Delta, 0, 1)$，被限制在 [0,1] 内，不会越界。
**第 2 步：其余按比例补偿。**其余思潮的原总和 $R = 1 - t$，为使总和仍等于 1，其余总和须变为 $1 - t'$，于是给所有「其他」乘同一缩放系数 $\text{scale} = \frac{1 - t'}{R}$，每个其余思潮的新占比为 $p_i' = p_i \times \text{scale}$（$i \ne k$）。
**结果：**总和恒为 1：$t' + \sum_{i \ne k} p_i' = t' + (1 - t') \times \frac{R}{R} = 1$。
**极端情况：**若 $R = 0$（其余全为 0，即 $t = 1$），无法按比例缩放，改平均分配：$p_i' = \frac{1 - t'}{n - 1} = \frac{-\Delta}{n - 1}$（$i \ne k$）。
这次修正中只更改了`add_ideology`/`add_interest_group` 的应用端。
</callout>

#### 2.2.2.2 情报机构

**情报机构**是玩家实际上管理的**机构**。玩家可以通过投入**行政力**增加**情报机构**各**部门**的产出。

##### 2.2.2.2.1 部门

**部门**是**情报机构**的手足，每个**部门**负责不同的领域，所需的**投入品**也各不相同。

###### 2.2.2.2.1.1 渗透处 🟢

**渗透处**是**情报机构**中负责渗透的**部门**，能够执行**渗透行动**与提高对非**核心区块**的**影响力**。

###### 2.2.2.2.1.1.1 渗透 ⁉️

玩家在下方导航栏点击渗透按钮，即可进入渗透模式。在该模式下，玩家可以自由选择主动**渗透**的对象，以提高对于非**核心区块**的**影响力**。  
玩家可以选择多个**区块**，但是玩家能选择的最大**区块**数量受**渗透处投入等级**的钳制。表现为：  
$最大可选择区块数 = (渗透处投入等级-1) × 2 + 3$

对于提升**影响力**的效果，也受**渗透处投入等级**的钳制。表现为：  
$每日影响力加成=渗透处投入等级×0.2$  
随着时间推移，**影响力**将逐渐向这一数值靠拢：

$$最终影响力加成=渗透处投入等级×10$$

对于**核心区块**，提供+10初始**影响力**。

当一个**区块**停止被**渗透**时，其因为**渗透**而获得加成的**影响力**将会以1/每日下降，直至未被渗透的状态。

**渗透处投入等级**范围为 1\~5 级（`MaxLevel = 5`）。

除了玩家主动选择的**渗透**外，某些**事件**选项还可以通过效果 `penetrate_block` 对指定**区块**进行**强制渗透**。**强制渗透**与主动**渗透**一样享受每日**影响力**加成，但不占用主动**渗透**的可选**区块**上限，也不会因主动取消而解除。

<callout emoji="💬">
设计观点备注
`PenetrationManager` 内部用独立的 `forced` 集合记录被**强制渗透**的**区块**，`MaxBlocks` 上限仅约束主动选择的**区块**数量。
</callout>

<callout emoji="❓">
设计观点备注
实际上，这种算法是线性的，它并不是像现实中有指数型或者其他形式的增长。在未来需要重新考虑算法的设计本身。
</callout>

###### 2.2.2.2.1.2 科技处 🟠

**科技处**是**情报机构**中负责科技研发的**部门**，能够增加我方的**破译难度**与降低敌方的**破译难度**。

###### 2.2.2.2.1.2.1 科技树

<cite doc-id="MaXPwxjUcicN78klN8Pcjgmpnqf" file-type="wiki" title="暗礁 科技树设计" type="doc"></cite>

###### 2.2.2.2.1.2.1 破译难度

**破译难度**是指获取特定**情报**的难度。降低其他**势力**的**破译难度**会使我方获得的**情报**更多，可能触发的**事件链**也更多；提高我方**破译难度**会使其他**势力**获得的**情报**更少，可能触发的**事件链**也更少。

###### 2.2.2.2.1.3 内务处 🟠

**内务处**是**情报机构**中督察**政府**的**部门**，能够提高**行政力**与**行政效率**。玩家初始拥有**行政力** 200（对应内务处一级）。

###### 2.2.2.2.1.4 情报处 🟠

**情报处**是处理**情报**并汇总报告的**部门**，能够拓宽**情报**获取的渠道，产出更详细的情报机构报告。

**情报处**会提供**情报点**，每多一级**情报处**等级就会额外提供**情报点**。玩家初始拥有**情报点** 50（对应情报处一级）。**情报点**是衡量**情报**密度的点数，每月所产出的**情报点**越多，触发**事件链**的概率也就越大。

##### 2.2.2.2.2 投入等级与资源 🆕

**情报机构**的四个**部门**都拥有 1\~5 级的**投入等级**（`MaxLevel = 5`）。玩家消耗**行政力**即可提升某一**部门**的**投入等级**，**投入等级**越高，该**部门**产出的效果越强。四个**部门**的开局**投入等级**均为 1 级。

###### 2.2.2.2.2.1 行政力

**行政力**（`AdministrativePower`，`ap`）是**情报机构**运转与扩张的基础资源，由**内务处**产出。系统在每次**逐日**结算时累加，产出表现为：  
$每日行政力产出 = 内务处投入等级 × 2$

例如**内务处**为一级时每日产出 2 点，三级时每日产出 6 点。**行政力**目前用于提升各部门的**投入等级**，未来也将用于支付**特别行动**等消耗。

###### 2.2.2.2.2.2 情报点

**情报点**（`IntelligencePoints`，`ip`）是衡量**情报**密度的资源，由**情报处**产出。系统在每个月的首日结算一次，产出表现为：  
$每月情报点产出 = 情报处投入等级 × 50$

**情报点**越多，触发**事件链**的概率越大。该概率的具体形式将随**事件链**系统（2.2.4.2）一并确定。

###### 2.2.2.2.2.3 投入等级

提升一个**部门**的**投入等级**需要消耗**行政力**，消耗量随目标等级递增：  
$升级消耗 = 100 × 当前投入等级$  
即一级升二级消耗 100 点，二级升三级消耗 200 点，逐级递增，单个**部门**升满合计消耗 1000 点**行政力**。降低**投入等级**时会返还该次升级消耗的一半，以避免误操作带来的资源损失。

各部门**投入等级**的效果汇总如下：

| 部门 | 投入等级效果 |
|-|-|
| 渗透处 | 最大可选区块数 = (等级−1)×2+3；每日影响力加成 = 等级×0.2；影响力加成上限 = 等级×10 |
| 科技处 | 提高我方破译难度、降低敌方破译难度（详见科技树设计，待实装） |
| 内务处 | 每日行政力产出 = 等级×2；行政效率 = 等级×0.2（待接入政府报告） |
| 情报处 | 每月情报点产出 = 等级×50 |

<callout emoji="💬">
实现状态
本节描述的是「资源与投入等级」的设计方案，**渗透处**的等级效果已经实装（见 `PenetrationManager`），其余三处的产出与消耗逻辑尚未实现；`TopBarUI` 中的**行政力**与**情报点**目前仍是静态初值。实装后本节将按源代码进行校对。
</callout>

### 2.2.3 情报

**情报**是玩家在游戏中获取信息的主要手段。**情报**分为一般情报与**重要情报**。

一般情报是指，很大程度上不会影响重大**事件**走向的**情报**；**重要情报**亦反。

#### 2.2.3.1 情报来源

**情报**的主要来源包含以下几个维度：

1. 国际社会影响巨大的**公共事件**
2. **政府**下发的**政府报告**
3. **情报机构**投入所产出的**情报机构报告**

这些**情报**来源，有些是真实可信的，有些是虚假错乱的。玩家需要通过多方对比求证来验证**情报**的**可信度**。

##### 2.2.3.1.1 政府报告

**政府报告**是获取**情报**的主要来源之一。*详见2.2.2.1.1 政府报告内容。*

月度**政府报告**会向玩家详细的展示民政系统与军队的数据，包括但不限于：

- **区块利益集团**占比
- **区块政治思潮**与其**政治力量**占比
- 国家的基本数据，如**意识形态**、**领导人**与**国际地位**、**外交关系** 
- 国家与**区块**的经济数据与**进出口**数据

政府的月度**政府报告**受**政府行政效率**钳制，使其**可信度**下降。

##### 2.2.3.1.2 情报机构报告

**情报机构报告**是玩家可自行掌握投入产出的**情报**来源，包括但不限于：

- 基于**渗透力**产出的**区块**与国家**情报**
- **特别行动**产出的**事件链情报**

**情报机构报告**受玩家选择的投入程度限制，使其产出的**情报**总量与**可信度**下降。

<callout emoji="💬">
设计观点备注
将玩家获取信息的能力截断为主动与被动、可信与不可信在政治游戏里是非常重要的一点。这个玩法的设计是为了让游戏本身具有“不确定性”。
</callout>

#### 2.2.3.2 重要情报

**重要情报**是指能够推动**事件链**产生的**情报**。**重要情报**具有**因果链**的属性，这决定**情报主管**为其标注的**可信度**。

<callout emoji="💬">
设计观点备注
我打算将间谍主管设计成传统的养成与指派系统，类似钢铁雄心与文明中的指派间谍或将领功能。可信度应该要受间谍主管本身的数值影响。
这意味着，我可能需要设计一套特质表来概括间谍主管可能的技能或者是精通度。
</callout>

##### 2.2.3.2.1 因果链 ⁉️

**因果链**是指**情报**在传播过程中，我们的特工对其可能的成因做出的推断。**因果链**的完整程度通常取决于玩家对**情报机构**的投入程度与在**事件**或**事件链**中的选择。

**因果链**的完整程度决定了这条**因果链**所提供的**重要情报**的**可信度**。

通常情况，**因果链**是不完整的，不完整的部分被称为**因果迷雾**。每一个**因果迷雾**都可能是一个**事件**或一条**事件链**所揭示的。

<callout emoji="⁉️">
设计观点备注
因果链作为游戏中最重要的系统之一，其最初是模仿维多利亚3中日志条目的设定而产生的，但是在这个项目里，日志条目的实际作用被事件链所取代了，所以因果链被重新定义为了“一种新的重要情报获取方式，并对事件链的走向作出重大影响的系统”。  
实际上，因果链的本质是一套紧密的条件判断系统。它会读取游戏目前的状态，并将是否开启路线分支这一条件传递给事件链系统。
在未来，我很有可能会给因果链添加模糊判断的机制，尤其是针对于起义、革命、分离事件链。不可否认的是，如果按照这个方向去走，游戏中将会内置数以百计的条件判断和无数细小的线索。
我将会在原型中试图逐步废弃“可信度”这一数值，转而向着某种能替代总结无数线索的表现形式发展。对于这个想法，我首先想到的是《底特律：化身为人》的存档界面与《崩坏：星穹铁道》的终末视界：似乎可以用类似Line的方式，通过玩家已掌握的线索，自动在界面中显露时间线或视角线的节点。这是对于“可能性”的一种概括。
同样的，我也考虑到了这种类似Line的方式不一定能承担“当前情报可不可信、该不该据此行动”的玩法判断。对于这类设计，我可能需要从更加偏向本格推理的角度去思考，但是这会更加把游戏的脑力消耗推高，反而过于硬核，对于开发本身也不现实。重要的是找到一个平衡点。
</callout>

###### 2.2.3.2.1.1 技术栈与UI表现 ⁉️

在实际开发过程中，**因果链**是囊括在一个JSON文件中的。系统通过冷加载的方式，在游戏开始时将JSON注入系统。每条**因果链**由 `id`（唯一标识）、`title`（标题）、`text`（揭示后的正文，可为空）、`locked`（初始是否处于**因果迷雾**打码）组成。

当某条**因果链**被揭示（`reveal_causal_chain` 效果）或更新描述（`set_chain_summary` 效果）时，会加入游戏界面左上角的**情报日志**面板。**情报日志**以卡片形式列出已揭示的**因果链**，卡片的标题与正文可直接阅读；仍处于**因果迷雾**中的**因果链**会显示「因果迷雾」打码占位，正文不可读。

<callout emoji="💬">
设计观点备注
`CausalChainManager` 负责加载与渲染**情报日志**。`locked` 为 `true` 且尚未被 `set_chain_summary` 更新的**因果链**会保持打码显示，直到对应**因果迷雾**被解锁。
</callout>

##### 2.2.3.2.2 因果迷雾 ⁉️

**因果迷雾**是能够采取**行动**或通过**事件**解锁的。对于**事件链**来说亦是如此。系统会通过冷加载的方式，在游戏开始时就将JSON注入系统中。**因果链**JSON的结构如下示例：

每条**因果链**由 `id`（唯一标识）、`title`（标题）、`text`（揭示后的正文，可为空）、`locked`（初始是否处于因果迷雾打码）组成；根对象 `chains` 为数组。

```json
{
  chains: [
    {
      id: spring_of_the_people,
      title: 人民之春,
      text: 第二次世界大战的结束，为整个世界带来新的黎明。然而，冷战的种子已经埋下，卢泰西亚暗流涌动。\n卢泰西亚究竟会走向何方？道路在脚下。,
      locked: true
    }
  ]
}
```

<callout emoji="❌">
设计观点备注
这个系统是受群星启发而做的，最重要的就是事件链。  
对于群星来说，事件链也是搞清楚“以前发生了什么事情”“以后会如何”的一套叙事玩法，这基本是写定的叙事逻辑。因果迷雾也是这样，其对于事件链的选项来说就是“必须达成的条件”。
如果因果链不明显，重要情报的可信度就会很低，玩家也没有办法剖析出推进事件链真正的条件。
</callout>

### 2.2.4 事件与事件链

#### 2.2.4.1 事件

**事件**是向玩家展示游戏中发生情况的游戏行为。通常来说，玩家的某一行为满足了某些条件后将会触发**事件**。**事件**通常会提供1\~5个**事件**选项，这些**事件**选项或是只是单纯基于数值增加，或是推动**事件链**继续或解锁**因果迷雾**。

##### 2.2.4.1.1 技术栈

在实际开发过程中，单一事件是囊括在一个JSON文件中的。系统会通过冷加载的方式，在游戏开始时就将JSON注入系统中。事件JSON的结构如下示例：

```JSON
{
      "id": "evt_start",
      "title": "新黎明",
      "story": "武装起来，公民们！\n组织起你们的队伍，\n前进，前进！\n只有敌人的不洁之血，\n才能灌溉我们的犁沟！",
      "description": "第二次世界大战的结束，为整个世界带来新的黎明。然而，冷战的种子已经埋下，卢泰西亚暗流涌动。\n作为新上任的间谍主管，请你带领卢泰西亚人民冲破迷雾，在历史上画出浓墨重彩的一笔。",
      "trigger": [
        { "type": "time_point", "year": 1945, "month": 9, "day": 4 }
      ],
      "options": [
        {
          "text": "卢泰西亚需要变革。",
          "hint": "这将暂时为卢泰西亚开启倒向社会主义阵营与民主主义阵营的选择。",
          "effects": [
            { "type": "add_influence", "blockId": "1008", "value": 20 },
            { "type": "set_flag", "flag": "revolution", "value": 1 }
          ]
        },
        {
          "text": "我们不能得罪法西斯！",
          "hint": "这将暂时为卢泰西亚断绝倒向社会主义阵营与民主主义阵营的选择。",
          "effects": [
            { "type": "add_influence", "blockId": "1008", "value": -10 },
            { "type": "set_flag", "flag": "revolution", "value": 0 }
          ]
        }
      ]
  }
```

每次开发会自动维护`type`的类型，并记录在案。若要查看所有`type`类型，请前往<cite doc-id="Uz22w3Yp4i86q2koCJHchaSEnzb" file-type="wiki" title="暗礁 type 对照表" type="doc"></cite>。

##### 2.2.4.1.2 触发机制

**事件**由**触发条件**（`trigger`）决定是否发生。系统每天推进时检查所有尚未触发过的**事件**，若某**事件**的全部**触发条件**同时满足，则立即触发该**事件**并暂停游戏。目前支持两类**触发条件**：

`time_point`：到达指定日期（`year`、`month`、`day`）。  
`flag_compare`：比较某个**标记**（`flag`）的数值（`flag`、`op`、`value`），其中 `op` 支持 `eq`（等于）、`ne`（不等于）、`gt`（大于）、`ge`（大于等于）、`lt`（小于）、`le`（小于等于）六种比较。

触发规则如下：每个**事件**只会触发一次，触发后记录其 `id`，不再重复触发；同一时刻若满足多个**事件**的**触发条件**，只触发其中第一个（按 JSON 中的顺序）。

<callout emoji="💬">
设计观点备注
**标记**（`flag`）是一组全局的浮点键值对，由**事件**选项的 `set_flag` 效果写入，供 `flag_compare` 条件读取，用于串联多个**事件**形成**事件链**的走向。
</callout>

#### 2.2.4.2 事件链

**事件链**是对多个相同情节范畴内的**事件**的总称，这些**事件**连环嵌套、联系紧密，并关系到游戏后续的主要玩法与剧情走向。

## 2.3 游戏结算

游戏的结算依附于叙事文本而非数值堆砌，这意味着，本游戏不存在一个既定的胜利结局，更多是依据剧情进行推进，并让游戏本身的叙事为结局做合理铺垫。
