# 2.0 Lead 裁决汇总（R-01…R-11）

public enum ChromeKind { Panel, Modal, Card, Strip }
public enum ChromeState { Normal, Disabled, Alert }

public static class UIPanelChrome {

# 8.0 宽度档位、网格与安全区

- 档位：**S=380**（详情面板、日志、事件 tooltip）、**M=620**（事件卡、渗透提示条）、**L=820**（机构总览）、**XS=300**（日期牌，特例）、**顶栏 stretch**（左 `TopBarLeftInset`=20、右 `TopBarRightInset`=340）。
- ❗**顶栏内缩与日期牌的关系（Lead 复核修正 · 第二版）**：日期牌在**右上角**（`Assets/Core/GameClock.cs:142-146`：`anchorMin=anchorMax=(1,1)`、`pivot=(1,1)`、`sizeDelta=(300,110)`、`anchoredPosition=(-20,-20)` → `x∈[W-320,W-20]`、`y∈[950,1060]`）。故**右内缩 340 = 日期牌宽 300 + 20 屏幕边距 + 20 间隙**（避免顶栏右端压住日期牌）；**左内缩 20 = 屏幕外边距**（左侧无构件，保留具名常量以便与右内缩成对）。`y` 上顶栏占 `[996,1060]`、日期牌占 `[950,1060]`，两者**x 完全分离**。
- 顶栏宽度与国名降级阈值：`W=1920` → 1560px（≥1200 全串）；`W=1600` → 1240px（≥1200 全串）；`W=1440` → 1080px（≥900 → `{国名} · {意识形态}`）；`W=1280` → 920px（≥900 同上）；`W≤1200` → ≤840px（只显示 `{国名}`）。
- 详情面板（右上、`x∈[W-380,W-20]`）与日期牌（右上、`x∈[W-320,W-20]`）在 x 上基本重叠，这正是 L-01 必须保留上 reserve 140 的原因。
- 面板安全矩形：`x∈[20, W-20]`、`y∈[100, H-90]`（下 = `SafeBottom`+`SafeInset`，上 = `SafeTop`+`SafeInset`）。
- 屏幕外边距统一 20；只有顶栏与底栏两条全宽带 stretch 到屏幕边。

# 16.0 验收期热修（Lead，用户实机反馈驱动）

## 16.1 冻结纪律（对后续所有改动的约束）

1. **凡"新建 UI 组件"的改动，都要按三类已知静默陷阱自查**：① 多组件互斥（`Graphic` 有 `[DisallowMultipleComponent]`，同一个 GameObject 上 `AddComponent<Image>` 返回 `null`）；② `Text.font == null` 时 UGUI **一个字都不画**（无报错）；③ `AddComponent` 会**同步执行** `Awake`（`UIButtonState.Apply` 里 mode 尚未赋值就 `Bind` 了一遍）。
2. **布局组只驱动直接子物体**：任何要"浮在按钮上、自己定位"的子层（如 `UIButtonState` 的 `Visual`）必须显式 `LayoutElement.ignoreLayout = true`，否则会被压成 0 尺寸，且其 `anchoredPosition` 会被每帧覆盖。
3. **被搬进 `ignoreLayout` 层的文本，父级布局组量不到它** → 需要自适应高度的行/卡，必须在构建时按文案长度算高度（`EventManager.OptionRowHeight` 是范式），不能靠行内 `ContentSizeFitter`。
4. **文案常量的"位置语义"以 `63_` 表为准**：`Event.OptionLead`(`批示`) 是选项区**上方小标**，不是每行前缀；程序不得把它拼进行文本。

5. **零运行期生成**：不得 `new Texture2D`、不得 `Sprite.Create`（延续 §1.0 禁令，`C1` 守着）。

## 17.5 门禁脚本硬规则（第三轮踩坑后补）

1. **`Tools\*.ps1` 要么纯 ASCII，要么存成「UTF-8 + BOM」。** 无 BOM 的 `.ps1` 在中文 Windows 上按 GBK 解码，GBK 的**尾字节配对**会把紧跟在汉字后面的那个 ASCII 字符（尤其是收尾的单引号 `'`）吞掉 → 整个脚本报 "string is missing the terminator"。第三轮的 N10 断言就死在这里：`'OptionLead \+ "：'` 里的全角冒号把收尾引号吃掉了，症状却是文件后半段到处报语法错（L384/L395/L409/L421/L433），极难定位。需要汉字就写成 `[char]0xFF1A` 这类码点拼装。**实测（2026-xx）**：`uipolish-check.ps1` 0 个非 ASCII 字节 ✓、`shader-check.ps1` 0 ✓、`visualpass-check.ps1` 423 个非 ASCII 但**带 BOM** ✓、`compile-check.ps1` 3 个非 ASCII 带 BOM ✓；⚠️ `run-preview.ps1` 30 个非 ASCII **且无 BOM**，是同一类定时炸弹（本轮未动它）。
2. **素材/资源类断言要真的读资源**：只做 `.cs` 正则 + 编译 + `git diff` 的门禁对"少一个 PNG、border 填错、wrap 写成 Clamp、漏关 `raycastTarget`"是全盲的（复核实测 0 命中）。H1a/H1b/H2/H3 就是补这个洞的，新增接入点时必须同步扩这四条。
3. **生成器要自带自检**：`Tools\gen-uiart.py` 写完全部 `.meta` 后逐件回读校验（`textureType: 8` / `spriteMeshType: 0` / `wrapU:0|1` / `spriteBorder` 与清单一致），不一致直接 `exit 2`，避免"契约写 Repeat、产物写 Clamp"这种事再次发生。另外**像素级自检**（`exit 3`）：`halftone_tile` 的 alpha 必须是 8px 整周期（否则 Repeat 平铺出接缝）、`grain_tile` 覆盖率 ≥0.5 且平均 alpha∈[0.005,0.15]、`vignette` 峰值 ≥0.5。
4. **断言数量不是证据，要能证明它抓得住**：第三方复核发现 H 块三条"假绿"（导入字段不在 needle 里、border 只做双向一致而不钉期望值、只数 `raycastTarget = false` 不查有没有被打开）。因此：① 期望值要**钉死**在门禁里，不要只做"两边一致"；② 新增接入点时必须**注入一次真实故障**看门禁是否 FAIL —— 用 `Tools\uipolish-mutation-test.ps1`（注入 3 类故障 → 期望 1 FAIL each → 恢复后用 SHA256 核对逐字节还原）。跑之前确认没有 Unity 导入/构建在跑（约 2 分钟里工作区带一个故障）。
5. **Python 生成器可以是 UTF-8 无 BOM**（Python 3 源码默认 UTF-8，`Tools\gen-uiart.py` 有 5359 个非 ASCII 字节且工作正常）；**这条豁免只给 `.py`，不给 `.ps1`**。

## 17.6 双产线分工：程序化纹理 vs Affinity 矢量（第三轮补做后新增）

`Assets/Resources/UIArt/` 里 14 件素材**不是同一条产线**，改任何一件之前先看清它的来源，别用错工具：

| 产线 | 素材 | 工具 | 特性 |
| --- | --- | --- | --- |
| **A. 程序化（噪声场）** | `paper_plate_9s`、`redaction_bar_9s`、`dossier_plate_9s`、`binding_dot`、`grain_tile`、`halftone_tile`、`vignette` | `Tools\gen-uiart.py`（确定性 seed） | 纤维/做旧/网点/暗角这类**随机场**，矢量工具做不出来 |
| **B1. Affinity 矢量 + 印泥后处理** | `stamp_weikaifang`、`stamp_shentou`、`stamp_jimi` | `Tools\.uiart\art-batch.js`（在 Affinity 里跑）+ `Tools\uiart-inkpass.py` | 矢量排版与印刷框线；印章文字必须**真字形**（`NotoSerifSC`），程序化描字读不清（实测平均 alpha 10/255） |
| **B2. Affinity 矢量 + 纸墨后处理** | `btn_plate_9s`、`titleplate_9s`、`rule_ring_9s`、`rule_ring_worn_9s` | `Tools\.uiart\art-chrome.js` + `Tools\uiart-chromepass.py` | 按钮压印、标题纸板底缘墨线、双线框的线口与断口靠矢量画准；质感（极轻颗粒 + 低频干墨）由后处理加 |

1. **`gen-uiart.py` 不得覆盖 B 类素材**：脚本里 `AFFINITY_ASSETS`（现为 3 章 + 4 件基底/边框，共 7 件）只登记 border 规格、`img=None`，主循环跳过写入。需要退回旧程序化版时显式跑 `python Tools\gen-uiart.py --force-pil`（旧名 `--force-stamps` 仍可用）。
2. **B 类素材的 `.meta` 仍由产线 A 的规格表管**：7 件 `spriteMeshType: 0`、`wrap=(1,1)`，border 与产线 A 同表（按钮 12 四边、标题 20,0,20,0、线环 8 四边、印章 0），改尺寸/改名必须同步改 `gen-uiart.py` 的清单与 `uipolish-check.ps1` 的 H 块期望表，否则 H1a 立即 FAIL。
3. **后处理必须可复现**：`uiart-inkpass.py` 用固定 seed（`20261016/17/18`）+ `numpy`；`uiart-chromepass.py` 用 `7101-7104`。任何"手抖改一个数"都要能重跑出来；旧版自动备份在 `Tools\.uiart\affinity\pil-backup\`。
4. **Affinity 脚本沙箱只允许写到 `Application.userDesktopPath`**：`Document.export / saveAs` 给任意绝对路径会 `PERMISSION_DENIED`。产物先落桌面 `reef-uiart\`，再由 Python 搬到项目里、由门禁校验。
5. **谁强用谁**（写进 §17.2 规则 1 的补充）：颜色仍由 token 给（B 类印章例外，章面自带朱砂、运行期 `color = white`）；结构靠矢量（框线、字形），质感靠噪声（纸、墨点、暗角）。任何"把纸底也改成 Affinity 纯色块"的改动都是**退化**，见 `Tools\.uiart\affinity-compare.png` 的对照。
6. **9-slice 素材的噪声幅度上限（B2 首版踩到）**：中区会被拉伸 5–12 倍，**高频噪声会被抹成条带**、而且任何偏向一侧的 RGB 调制都会让整块素材偏离 token 颜色。硬规则：中区颗粒幅度 ≤ 4%（`uiart-chromepass.py` 取 0.03–0.035，RGB 起伏必须**对称**±1.2%，均值 1.0）；干墨之类的纹理必须是**低频**（噪声源降到 1/6 尺寸再放大）。首版用 grain 0.16 + RGB 0.965–1.0，结果按钮整块暗 1.7% 且出现竖向条纹，已作废。
