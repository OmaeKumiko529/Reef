## 2.2 材质与渲染：MaterialPropertyBlock 方案

**根因（必须先修 shader，否则 MPB 只是"不脏盘"）**：`Assets/Province/ProvinceSelect.shader:84` 用 `_BaseMap` 同时承担两个语义——既当"底色来源"，又当"身份图"；`:90` / `:111-112` 的描边判据是 `SameId(selfId/neighbor, _SelectedId)`，`selfId` 与邻域全部取自 `_BaseMap`。而 `Assets/Agency/PenetrationManager.cs:197` 把 `_BaseMap` 换成 `penMap`（绿/灰），`penMap` 的像素值来自 `:191-192` 的 `PenGreen` 或 `ToGray`，于是 `SameId` 永远为假 → 渗透模式下描边与填充整体失效（`优化评审报告.md` 的 P2-3）。所以"改用 MPB"要和"拆开两张图"一起做。

**改动点清单（按依赖顺序）**

1. `Assets/Province/ProvinceSelect.shader:5-13`：新增 `_IdMap ("ID Map", 2D) = "white" {}`；`:35-39` 增加 `TEXTURE2D(_IdMap); SAMPLER(sampler_IdMap); float4 _IdMap_ST; float4 _IdMap_TexelSize;`；`:63` 的 `TRANSFORM_TEX(v.uv, _BaseMap)` 保持不变，但需在顶点里另算 `i.uvId = TRANSFORM_TEX(v.uv, _IdMap)`。
2. `Assets/Province/ProvinceSelect.shader:84` 改为 `selfId = SAMPLE_TEXTURE2D(_IdMap, sampler_IdMap, i.uvId).rgb;`（**色彩显示与身份判定都继续取自 ID 图**）；`:94` 的 `px` 与 `:111` 的 8 邻域全部换成 `_IdMap_TexelSize` + `sampler_IdMap`。这样"底色"与"身份"彻底解耦。
3. 显示色仍走 `:85` 的 `SRGBToLinear(selfId)`——即省名标签/描边看到的是 ID 图原色。**取舍**：不把 `_BaseMap` 的 ID 语义拿掉（不动美术在 `MapMat.mat:41-45` 里配的 `_BaseMap = map.png`），而是**让 `_BaseMap` 专职"显示/底色"，`_IdMap` 专职"身份"**；代价是 shader 多 8 次采样（描边分支本来就 8 次，无净增）。
4. `Assets/Province/ProvinceClickHandler.cs:40-41`、`:67-68`、`:73-82`：把 `mapMaterial.SetVector/SetFloat` 全部改写为 `mpb.SetVector/SetFloat` + `renderer.SetPropertyBlock(mpb)`。`:35-39` 的 `Vector4` 计算保持原样（**不要把 `_SelectedId` 改回 `Color`**，理由见 shader `:6-7` 注释与 Linear 项目下的 sRGB 自动转换）。
5. 渲染器引用来源：`SampleScene.unity:466-470` 显示 `Map` 这个 GameObject 同时挂 `MeshCollider`(`:508`)、`ProvincePicker`(`:487`)、`ProvinceClickHandler`(`:612-615`)；MeshRenderer 在同一 GameObject 上（场景里 `mapMaterial` 与渲染器引用同一材质 guid `5da2ebbcf6af93b4f9ee9e950c4d78c3`）。因此 `ProvinceClickHandler.Awake` 里 `GetComponent<MeshRenderer>()` 即可拿到，无需改场景、无需新字段。
6. `Assets/Agency/PenetrationManager.cs:197/203` 两处 `mapMaterial.SetTexture("_BaseMap", ...)` 改为 `mpb.SetTexture("_BaseMap", penMap/idMap)`。**但 `Setup` 的签名只有 `Material`（`:74-81`）**，调用点在 `Assets/Province/ProvincePicker.cs:32`。建议追加可选参数（`MeshRenderer renderer = null`）而不是改建新方法，保持向后兼容；由 `ProvincePicker` 传同一个 `GetComponent<MeshRenderer>()`。
7. 属性名统一：把 `"_SelectedId"`、`"_HasSelection"`、`"_SelectionBlend"`、`"_BaseMap"`、`"_IdMap"` 用 `Shader.PropertyToID` 缓存一次。**`SetFloat/SetVector(string,...)` 在属性名拼错时不报错、静默无效**，这是本项最大的隐形风险。

**两个必须知道的坑**

- `_IdMap_TexelSize` **不会**被 MPB 自动填充。纹理型属性的"每纹理派生常量"依赖材质侧的 `TexturePropertyName` 声明；MPB 只透传显式设置的值。本 shader 已经在 `:39` 手写声明 `float4 _BaseMap_TexelSize`，所以就按同样方式加 `_IdMap_TexelSize`，并在 C# 里显式 `mpb.SetVector("_IdMap_TexelSize", new Vector4(1f/w, 1f/h, w, h))`（`w/h` 来自 `idMap.width/height`，`PenetrationManager.cs:184-185` 已有该尺寸）。
- `MapMat.mat:118 / :126 / :142` 里已经烘焙进运行期状态（`_HasSelection: 1`、`_SelectionBlend: 1`、`_SelectedId` = 1008 号色 `#1C3994`）。改 MPB **不会**自动清掉这三项——只要有一个渲染路径没走 MPB，开局仍是"1008 已选中"。**建议与 2.2 同批做**：把 `.mat` 的三项复位为 `0 / 0 / (0,0,0,0)`，并在 `ProvinceClickHandler.Awake` 里显式 `ClearSelection()` 一次。
- 附带收益：MPB 是"少样本通道"，与 `优化评审报告.md` 的 P0-5（每次点选重建整张 267 万像素 `penMap`）可以合并处理——`ApplyPenMap` 改成只回写变化省份的像素区间后，`mpb.SetTexture` 每帧重设的成本可以忽略（属性值没变时几乎零开销），不必再判脏。
- 不确定项 ❓：URP 下"Renderer 带 MPB"通常会让该渲染器退出 SRP Batcher（走 SetPass 兼容路径）。本项目只有 1 个 quad（`SampleScene.unity:529/586` 同一内置 Quad mesh），无实际损失；但这条我**没有在本机实测 URP 17.5 的行为**，按"不确定"记录。

## 2.3 相机：开局自适应 / 钳制 / 光标锚定 / 复位

**事实基线**：相机为正交（`SampleScene.unity:184` `orthographic: 1`），`orthographic size: 5`（`:185`），位置 `(0,10,0)`、绕 X 轴 90°（`:209-210`），朝下俯视 y=0 平面；地图是内置 Quad 缩放 `(16,12,1)`（`:597`）。所以纵向可见单位 = `2 × 5 = 10 < 12`，纵向约 1/6 在屏外；横向可见 = `10 × aspect`，16:9 时为 17.78 > 16，横向反而有余量。

**正交相机的几个数学要点**（写代码时按这个来，不要凭感觉）

- 俯视正交相机在 y=0 平面上的可见矩形：半高 `h = orthographicSize`，半宽 `w = orthographicSize * cam.aspect`，中心即 `cam.transform.position` 在 xz 上的投影。
- **开局自适应**：`fitSize = Mathf.Max(bounds.extents.y, bounds.extents.x / cam.aspect) * 1.06f`（6% 余量给描边和省名标签）。地图世界边界**从场景派生**而不是硬编码：`SampleScene.unity:529/586` 是同一份 built-in Quad（本地 bounds 1×1），乘以 `:597` 的 `(16,12,1)` → 世界 `[-8,8] × [-6,6]`（`y=0`）。运行时用 `renderer.bounds`（世界空间）或 `mesh.bounds + lossyScale` 都行，前者更省事。fit 后 `maxZoom` 至少要让用户能拉到"略大于整图"，建议 `maxZoom = fitSize * 2`，`minZoom = fitSize * 0.25`（`CameraPanController.cs:21-23` 现有的 2/20 是场景里配的，别只靠 Inspector 值）。
- **平移钳制**：`cx` 限制在 `[min.x - (w - ext.x), max.x + (w - ext.x)]`，`cz` 同理用 `h`。当 `w <= ext.x` 时公式退化为"必须严格在地图内"，这正是"拖不丢"的来源；当 `w > ext.x`（拉得比地图还远）时应该直接锁中心而不是允许看到空旷背景，否则一拉远就能把地图拖到角上。钳制要作用在 `targetPosition` 上（`CameraPanController.cs:74-75` 之后），而不是平滑后的当前位置。
- **缩放锚定光标**：滚动时先求"光标下的世界点" `p = ScreenToWorldPoint(mouse)`（y=0 平面），记下缩放前的 `h0 = orthographicSize`，算出缩放后 `h1`，把相机目标位置平移 `delta = p - newScreenCenterUnderCursorOffset`——即 `targetPosition.x += (0.5 - mouseNorm.x) * 2 * (h0 - h1) * aspect`、`z` 用 `h` 而不是 `aspect`。这样光标下的省份在缩放前后停在同一点。
- **每帧写 transform**：`:80-86` 无条件写 `transform.position` 与 `orthographicSize`，而 `SmoothDamp` 是渐近收敛（`优化评审报告.md` P1-4 已指出）。改法：加一个"远未到位/已到位"判定——`if ((pos - target).sqrMagnitude < 1e-6f && vel.sqrMagnitude < 1e-6f) { 直接赋值并 return; }`，静止时彻底不写。

**改动点清单**：`CameraPanController.cs` 内新增 `FitToMap()`（Awake 末尾调一次）、`ClampTarget()`、`ZoomAtCursor(Vector2)`、`public void ResetView()`（= `FitToMap()` + 清 velocity）；`:51-63` 的滚轮分支改为调用 `ZoomAtCursor`；`:80-86` 改为"有变化才写"。**复位入口**：`R` 键与 `Home` 键（`GameClock.cs:74` 已有 `Keyboard.current.spaceKey` 的用法，照抄即合法；全项目零处 `UnityEngine.Input`，不要引入旧输入 API），外加角落一个按钮（按钮建议走 2.5 的 `UIFactory.CreateButton`）。地图边界通过 `[SerializeField] Renderer mapRenderer` 暴露，缺省时在 `Awake` 里 `FindFirstObjectByType<MeshRenderer>()` 兜底并允许 Inspector 覆盖。

不确定项 ❓：滚轮量纲（`CameraPanController.cs:56` 的 `scroll * zoomSpeed`）依赖 Input System 的 `scrollDeltaBehavior` 默认归一化；`优化评审报告.md` P1-4 已确认当前行为正确但建立在不可见设置上。本轮不改该语义，只在其外围加钳制；若后续有人改 `KeepPlatformSpecificInputRange`，应改为 `Mathf.Sign(scroll)`。

## 2.4 省名标签：IMGUI → UGUI

**现状**：`Assets/Province/ProvinceLabelUI.cs:52-75` 用 `OnGUI`（每帧 Layout + Repaint 各一次）、`:25` 固定 `fontSize = 30`、`:68-69` 固定 `260×40`、`:58` 每帧 `Camera.main`（带 tag 查找）、`:62` 只判 `screen.z < 0` 不判屏幕边界；`:73` 注释说明是**故意去掉阴影**的（为避开重影）。它与 UGUI 的 `CanvasScaler`（1920×1080，`UIFactory.cs:19`）是两套坐标系。

**调用契约（不要动这两个签名）**：`Assets/Province/ProvincePicker.cs:109` 调 `labelUI.Show(centroid, province.displayName)`、`:79/:86/:118` 调 `Hide()`；`ProvincePicker.cs:28` 在 `labelUI` 为空时 `AddComponent<ProvinceLabelUI>()`（场景里 `SampleScene.unity:491` 的 `labelUI` 是 `{fileID: 0}`，所以**运行时一定是代码挂上去的**）。只要 `Show(Vector3 worldPos, string text)` / `Hide()` 保持不变，调用方零改动。

**迁移方案**：`ProvinceLabelUI` 内部改成自建 UGUI——一个独立 `Canvas`（ScreenSpaceOverlay）+ 一个 `raycastTarget = false` 的 `Text`；`Show/Hide` 只置 `visible` 与缓存 `worldPos`，`LateUpdate` 里做投影与位置更新。要点：

- 投影：`cam.WorldToScreenPoint(worldPos)` → `screen.z < 0` 判背后 → `RectTransformUtility.ScreenPointToLocalPointInRectangle(canvasRect, screen, null, out local)`；`null` 是因为 Overlay 模式没有相机（写 `cam` 会算出错误坐标）。
- **裁剪**：先做一次"屏幕矩形内 + 内缩 130/20 像素（标签半宽半高）"判定，越界就 `enabled = false` 式隐藏；再交给 `Canvas` 的 `RectMask2D`/父级 `RectTransform` 裁剪兜底。注意 `Text` 默认 `horizontalOverflow = Wrap`（`UIFactory.cs:33`），所以 `RectTransform` 必须显式给宽（260×40 这个经验值可以保留）。
- **别每帧写 `transform.localPosition`**：先判 `local != lastLocal`，相等就跳过（`Graphic` 的布局重建是脏驱动的，位置不变就不会重算）。
- 字体：场景里 `ProvincePicker.labelFont` 指向 `guid: f882f52a217179c43991c538578bd6cc`（`SampleScene.unity:492`），即 `Assets/Fonts/NotoSerifSC-VariableFont_wght.ttf`（25 MB，`优化评审报告.md` P1-12）。legacy `Text` 用可变字体时只有默认字重；`UITheme` 现在没有描边色常量，需要给标签单独定一个**深墨色**（`UITheme.cs:8` 的 `InkPrimary #2A2318`）。**可读性方案（按代价从低到高）**：① 先做 `Shadow`（offset 1px、深墨、`effectDistance = (1,-1)`）——代价极低且能解决"白字落在浅色纸面"的对比度问题；② 需要更强再上 `Outline`（8 方向复制顶点，标签只有 1~5 个字，可接受）；❓不确定：故意去阴影（`:73` 注释）是为避开什么具体重影，需美术确认后决定是否保留无阴影。
- **每帧成本**：迁移后每帧只剩一次 `WorldToScreenPoint` + 一次位置比较，**无 `Camera.main` 查找、无 GUIStyle 同步、无 IMGUI 双份回调**，比现状更省。`OnGUI` 的 GC 与 IMGUI 事件开销彻底消失。

## 2.6 交互与反馈

- **文字遮挡点击**：连同上节。另注意 `ProvincePicker.cs:54-65` 的 `RaycastAll` + `new PointerEventData` + `new List<RaycastResult>` 是**每次左键点击一次分配**，不是每帧，量级可接受但可以顺手改成 `EventSystem.current.IsPointerOverGameObject()`。
- **悬停反馈（高亮/光标）是目前完全缺失的**（全项目零处 `Cursor.` 调用，`EventSystem` 只被 `ProvincePicker` 用于判定 UI）。实现路径，按性价比排序：① 在 `ProvincePicker.Update` 里用限频（每 2~3 帧一次）`Physics.Raycast` 求当前省份，把 `Cursor.SetCursor` 或 `Cursor.lockState`/自定义光标切到"手型"；② 真正的高亮不必新增 shader 参数——**复用 `_SelectedId` + `_HasSelection` 做"悬停预览"会更省**，但会与真正的选中态抢同一个属性，建议先只做光标 + 标签跟随，高亮留到"选中态语义定了以后"；③ 拾取路径本来就已经有 `ProvincePicker.cs:76-96` 的全套逻辑，悬停只是把 `wasPressedThisFrame` 换成"每帧"，**注意 `:137` 的 `ComputeCentroid` 是全图扫描，悬停绝不能走这条路**（P0-4），悬停必须用预计算的重心缓存。
- **渗透模式 N/11 进度**：`MaxBlocks` 是算出来的（`PenetrationManager.cs:41`，1 级 = 3，5 级 = 11），提示条文案写死在 `:242`。接入点：① `:242` 的文案改成带计数的动态文本；② 在 `:106-126` 的 `Toggle` 与 `:128-137` 的 `ForcePenetrate` 之后刷新该文本；③ 新增 `event Action OnStateChanged`（`优化评审报告.md` P1-7 的同一条建议，能一起解决底栏高亮漏刷新）；④ `:120` 的 `if (penetrating.Count - forced.Count >= MaxBlocks) return;` 是**静默失败**——玩家点到上限没有任何反馈，应改为一次提示（文案变色或 `UIAnim` 闪一下）。

## 2.7 风险清单与回退

| # | 风险 | 可能出错的方式 | 回退方式 |
|---|---|---|---|
| R1 | shader property 名不一致 | C# 里 `SetFloat("_Haselection")` 拼错 → **不报错、静默无效**；`_IdMap` 改了 C# 没改 shader → 描边永远不显示 | 全部走 `Shader.PropertyToID` 常量；改完在编辑器里对着一个省点一次，肉眼确认描边 |

## 2.8 主张的实施顺序（每步独立可验证、可回退）

1. **相机**（纯 C#，零资产风险）：fit + 钳制 + 光标锚定 + 复位 + 静止不写 transform。
2. **shader 拆 `_IdMap`**：只加属性与采样，`_BaseMap` 语义不变；确认地图外观与描边与改动前一致。
3. **MPB 化 + 复位 `MapMat.mat` 烘焙状态**：这一步同时解决"开局自带 1008 高亮"与"渗透模式描边失效"。
4. **`PenetrationManager` 增量回写 `penMap`**（P0-5）：把每次点击的 267 万像素重建降为按省区间回写，顺带让 MPB 的 `SetTexture` 变成低频调用。
5. **UI 基建两连**（先 `raycastTarget`，后 `matchWidthOrHeight` + 排序常量）。
6. **省名标签迁 UGUI**（保留 `Show/Hide` 契约）。
7. **悬停光标 + N/11 进度 + `OnStateChanged` 事件**（顺带修底栏高亮漏刷新）。
