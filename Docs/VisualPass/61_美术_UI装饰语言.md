## 1.0 结论摘要

1. 现在像原型的根因不是"没加装饰"，而是**面板只有一层纯色 Image**：`Image.sprite == null` 时它只能画实心矩形，画不出边、角、投影（`Assets/UI/UIFactory.cs:74-85` 的 `CreatePanel` 只设颜色），所以七块面板之间只有色差、没有"纸张边界"。
2. 第二个根因是**交互零反馈**：全项目四处按钮都是 `Selectable.Transition.None`（`UIFactory.cs:111`、`AgencyNavUI.cs:135`、`GameClock.cs:165`、`EventManager.cs:374`），`UITheme.StateHover`/`StateSelected`（`UITheme.cs:47-48`）**全项目零消费**，已声明的五态一次都没生效过。
3. 用户说的"错位"有可核对的机制：九种面板宽度（300/360/380/420/560/620/700/820/1000）、十种内边距（8/10/12/14/18/20/24/30，且 `GameClock` 一个面板内 10 与 20 并存）、外边距 0/20/460 三种并存，详见 §2.1。
4. 装饰语言定为**「公文呈报」**：双线框 + 铅字标题栏 + 朱砂印章 + 档号角标（§7.0），全部由 1px 实心 Image 与文字旋转拼出，零贴图、零 shader。
5. ❌ **圆角不做**（契约 R-01 裁决为直角双线框，理由与作废项见 §2.3）；替代柔和感的是内高光 + 压痕 + 硬投影三层关系。

### 2.3 圆角：❌ 不做（契约 R-01 已裁决）

理由有三条：①`Image` 无 Sprite 时不能圆角，必须程序生成贴图并让**所有**面板改走 `Image.type=Sliced`，9 处迁移任何一处漏改就出现直角/圆角混用；②更关键的是**假描边与圆角不兼容**——描边若仍是矩形外扩 Image，圆角面板的四角会露出墨色小方块，必须连描边一起换成同一张 9-slice，风险成倍；③档案纸/铅字/印章的语言本来就是**直角**（纸边、裁切线、双线框），圆角属于现代卡片 UI 语言，与 1945 档案基调冲突。
**裁决结果（契约 R-01）**：改**直角双线框**；判据 P9「程序化 9-slice 生成器」整条撤销（零 `Texture2D`、零 `Sprite.Create`）；本文原"若做圆角"的 9-slice 参数、以及一切只为圆角服务的 token（圆角半径 / 九宫格 / 圆形节点贴图）**全部作废、不再给值**；既有 `UITheme.PanelRadius = 6f`（`Assets/UI/UITheme.cs:34`）**保持原值、不删不改**，全项目零消费，登记为 P2 预留。

## 7.0 视觉锤

**主提案「公文呈报」**（恰好一个）：每块面板都是"一份归档公文"——顶部报头是红头（朱砂竖块 + 2px 墨线），面板标题栏是铅字抬头，右上角挂档号角标，右下角盖朱砂印章，正文数值行走点线引导。它服务的信息是**面板身份与状态**（哪份公文、已归档/未开放/机密），不是纯装饰：印章与档号让"未开放部门"和"锁定卡片"有体面的诚实表达，替代现在的假进度与灰按钮。
纯代码可行性：✅ 全部可做（1px Image、色块、Text、`localRotation` 旋转、`EaseOutBack` 缩放）；❌ 做不到的是真圆形印章、真圆点装订孔、纸张纹理（都需贴图），替代为**方形印章 + 方形装订点 + 两档纸色**。**备选「装订册」**：左缘装订点列 + 卡片堆叠 + 页码角标，同样纯代码可做。策划 task-12 尚未定稿；若契约选别的方向，只要不含圆角卡片/纸质纹理/圆形印章，本文件 §2.0–§6.0 的规格均可原样复用。

## 8.0 交给程序的 `UIPanelChrome`（绘制顺序 = 兄弟顺序，从底到顶）

0 `Shadow`（投影层）→ 1 `DoubleLine`（`Divider`@0.9，外扩 3px）→ 2 `Frame`（`InkPrimary`@0.55，外扩 1px）→ 3 `Paper`（纸底）→ 4 `Highlight`（顶部 1px）+ `Press`（底部 1px）→ 5 `TitleBar`（底 + 朱砂竖块 + 标题 + 2px 下沿线）→ 6 `Content`（**返回给调用方**的内容区根）→ 7 `DossierTag`（档号角标，右上）→ 8 `Stamp`（朱砂印章，右下，可选）。
**契约 R-07 冻结的形态（"句柄 + 增量"，逐字签名见契约 §6.0）**：`UIPanelChrome.Create(parent, name, kind, title, size, anchor, pivot, anchoredPos, sortingOrder)` 返回 `PanelChrome` 句柄，`chrome.Content` 即内容区根（**满足本文"内容区根返回给调用方"的要求**）；增量方法 `AddBorder(host, inset, color)`、`AddTitleBar(host, title, height = 56f)`、`AddDivider(parent, topOffset)` 供顶栏/日期牌/底栏/提示条这四条不宜整体重写布局的带条使用；另有 `AddShadow(Graphic)`、`SetStamp(c, text, show)`、`SetDossierTag(c, text)`、`SetState(c, state)`。
本文原建议的 `RectTransform CreateChrome(Transform parent, string title, Vector2 size, Vector2 anchor, Vector2 pivot, Vector2 offset, ChromeKind kind = ChromeKind.Panel)` 形态**作为补充说明保留**（两版不冲突）：`kind` 取 `Panel`(纸底+双线+标题栏) / `Modal`(深墨反白标题栏) / `Card`(无标题栏、单线) / `Strip`(提示条、无投影)；五态统一交给 `UIButtonState.Apply(Button, ButtonMode)`（`UIFactory.CreateButton` 默认挂 `Action`）；`UIFactory` 另需补 `CreateLine(parent, color, height)` 与 `CreateBlock(parent, color, size)`。
❗纪律（契约 R-08）：所有装饰只在创建时构建一次，**禁止每帧 new Texture2D/Sprite/Image**；本方案**不需要任何 Texture2D**（R-01 已撤销 9-slice；划线/色块/文字都是现成 Graphic）；所有装饰图元（外框/双线/高光/压痕/投影/竖块/分隔线/打码条/印章/档号角标/贯穿线/节点）一律 `raycastTarget=false`，只有纸底与按钮为 true。
