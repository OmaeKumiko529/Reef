**讨论中被否决或修正的主张**（每条都留了"为什么"）：

1. **圆角 6±1px → 否决，改直角双层框**。理由：`Image.sprite == null` 时纯色四边形画不出跟随圆角的 1px 描边；要做圆角必须整圈换成 9-slice 贴图或程序化 `Sprite`，与"零新增美术资源"和 1px 线条保真度双重冲突。1945 年档案纸的语汇本身也是直角。
2. **悬停上浮 2px → 修正为 1px**。理由：2px 位移在密集 HUD 里会被读成"抖动"，1px + 金边变色已足够表达可点。
3. **日志/事件宽度 560 → 修正为收敛集合 S=380 / M=620 / L=820**。理由：560 不在集合内（会变成第 4 种宽度）；380 让日志抽屉与 820 的机构面板在最窄比例下也不重叠。
4. **Lead 自报的"顶栏左内缩 360（避让左上日期牌）"→ 被美术实测推翻**。`Assets/Core/GameClock.cs:142-146` 实测日期牌在**右上角**（`anchor/pivot=(1,1)`、`sizeDelta=(300,110)`、`anchoredPosition=(-20,-20)` → `x∈[1600,1900]`）。改为**左 20 / 右 340**：右 340 = 日期牌 300 + 20 边距 + 20 间隙，左 20 = 屏幕外边距。这条是"子代理反驳 Lead"的实例，**以实测为准**。
5. **卡片左缘节点 8×8 → 修正为 `BindingDotSize`=4**（旧稿数字作废，值以 token 为单源；程序拒绝为迁就文档造值是对的）。
6. **日志锁定卡"印正文 + `Redacted` 染色"→ 判为总纲违约**，改为打码条 + 标题位写「因果迷雾」。这是本轮唯一的**功能级**修正。
7. **死 UI 不修而是删**：`Assets/Agency/AgencyNavUI.cs` 里 620×420 的部门面板对 5 个入口**全不可达**（`:234` 拦截 + `:288-309` 分流），本来就不是玩家可见错位，删掉比"修"更对。

## 71.3 玩家可见变化（验收清单）

前 6 条是"边框/装饰/成品感"，第 7–9 条是"错位与层序"，第 10–11 条是"耳目一新的点"。

2. **右上日期牌卡片化**：纸底 + 双层框 + 投影 + 标题栏，字号档位统一（不再与顶栏各占一个高度档）。

## 71.12 实机运行热修（验收期，用户首跑后）

静态门禁全绿**不等于**能跑起来：本轮 UI 在用户第一次进 Play 时报错中断，随后又查出两条"不崩但看不见"的静默缺陷。三条都已修复，并各配一条断言，记录如下（`Assets/Scene/SampleScene.unity` 全程未改）。

### 71.12.1 🔴 崩溃：`UIPanelChrome.CreateStretched` NRE（用户实机报错）

```
NullReferenceException: Object reference not set to an instance of an object
UIPanelChrome.CreateStretched (...) (at Assets/UI/UIPanelChrome.cs:157)
  ← PenetrationManager.EnsureHint (…:287) ← PenetrationManager.Setup (…:104) ← ProvincePicker.Awake (…:38)
```

- **机理**：`UnityEngine.UI.Graphic` 带 `[DisallowMultipleComponent]`（`Library/PackageCache/com.unity.ugui@…/Runtime/UGUI/UI/Core/Graphic.cs:17`），在**已有 `Text` 的物体上**再 `AddComponent<Image>()` 返回 `null`（Unity 仅记一条 “Can't add 'Image' … because a 'Text' is already added”），紧随其后的 `c.Stamp.color` 抛 NRE。
- **影响面**：该段在每个面板创建时都走到 → `ProvincePicker.Awake` 在第 38 行（**第一个**管理器）中断，`BlockManager / AgencyNavUI / AgencyPanelUI / GameClock / EventManager / CausalChainManager / TopBarUI` 全部未创建；玩家表现为"只能拖动地图，点不了任何东西"（相机不在该链路上）。
- **修法**：印章句柄改挂**独立** GameObject `StampName + "Handle"`（`Assets/UI/UIPanelChrome.cs:163-171`）。
- **护栏**：断言 `N4` = Assets 下禁止 `AddComponent<Image|Text|RawImage|Graphic>`；`N5` = 印章句柄必须是独立 GameObject。同类陷阱不止 Graphic（`Selectable / Mask / RectMask2D / LayoutGroup / CanvasScaler / AspectRatioFitter / EventSystem / ScrollRect / ToggleGroup` 都带该特性），规则统一为"`AddComponent<T>` 前先 `GetComponent<T>` 判空"。

### 71.12.2 🟠 静默空白：`Text.font == null` 时 UGUI 一个字都不画

- **机理**：UGUI `Text.OnPopulateMesh` 首行即 `if (font == null) return;`（`…/Text.cs:661-662`），默认字体只在**编辑器** `Reset()` 里赋（`Text.cs:585-591`），运行期 `AddComponent<Text>()` 不会调用它，也不报错（`FontUpdateTracker.cs:23` 同样直接 return）。
- **影响面**：`UIPanelChrome` 的 5 处内建文字（标题栏 `:260`、眉标 `:278`、档号角标 `:134`、面板印章 `:153`、`MakeSeal` 印章 `:387`）字体实参全是 `null` → 省情档案标题、机构总览标题+眉标、情报日志标题+「卷宗 01」、未开放斜章文字全部空白。
- **修法**（比逐个传参更彻底）：`Assets/UI/UIFactory.cs` 新增 `public static Font DefaultFont`（`:28`），`CreateText` 的解析顺序改为「调用方显式给的 → 第一个见过的非空字体 → `DefaultFont`」（`:57-65`）；`Assets/Province/ProvincePicker.cs:31-38` 在 `Awake` **第一步**把场景字体写入 `UIFactory.DefaultFont`，若为空则 `Debug.LogError`（把"静默全空白"变成可诊断）。
- **护栏**：断言 `N6` = 字体兜底接线（`DefaultFont` 存在 + `font = DefaultFont` 分支 + `ProvincePicker` 赋值）。

### 71.12.3 🟠 静默失效：`UIButtonState` 选中条永远建不出来

- **机理**：`Apply` 里 `AddComponent<UIButtonState>()` 会**同步**触发 `Awake→Bind`，那一刻 `mode` 仍是默认的 `Action`（`NavBar/Option` 的选中条分支被跳过）且 `bound` 立刻置 `true`；随后 `s.mode = mode; s.Bind();` 被 `if (bound) return;` 整段挡掉 ⇒ `bar` 恒为 `null`。
- **影响面**：底栏 5 个入口（`Assets/Agency/AgencyNavUI.cs:157`）与事件选项行（`Assets/Event/EventManager.cs:410`）的选中态整体不可见 —— 而 `BtnSelectedBg` 与常态近同色，"当前是渗透还是机构模式"唯一强信号就是那条 3px 条。
- **修法**：抽出可重入的 `EnsureSelectedBar()`（`Assets/UI/UIButtonState.cs:105-133`，`bar != null` 或 mode 非 `NavBar/Option` 即返回），`Bind()` 末尾与 `Apply()` 设完 mode 之后各调用一次；`Refresh()` 的显隐条件补上 mode 判定（`:185`）。
- **护栏**：断言 `N7` = `EnsureSelectedBar` 在设完 mode 后被补调（`Apply` 内调用序列 + 调用点计数 ≥3）；`N8` = 选中条显隐受 `NavBar/Option` 约束。

### 71.12.5 🟠 选项行文本错位（用户第二跑反馈：`m01617`）

三处叠加，全部集中在事件卡选项行 `Assets/Event/EventManager.cs` 与 `Assets/UI/UIButtonState.cs`：

1. 🔴 **`UIButtonState.Bind()` 建出的 `Visual` 层被"按钮自身的布局组"当排版行接管**。选项行原有自己的 `VerticalLayoutGroup`（`childControlHeight = true`），布局组只会管**直接子物体**：`Visual` 没有 `ILayoutElement`，被压成 0 高度 → 搬进 `Visual` 的标签（锚点拉伸、`verticalOverflow` 默认 `Truncate`）跟着塌陷／只画在行顶；同时布局组每帧重写 `visual.anchoredPosition`，把"悬停上浮 1px"覆盖掉。
   **修复**：`Visual` 显式 `LayoutElement.ignoreLayout = true`（护栏 `N9`）。
2. 🟠 **行高算不出来**：标签既然被搬进 `ignoreLayout` 的 `Visual`，容器 `Options` 的 `VerticalLayoutGroup` 就**永远量不到**标签 → 行内再挂 `VerticalLayoutGroup + ContentSizeFitter` 结构上也自adaptive不了（实测行高退化成 `LayoutElement.minHeight`）。**修复**：删掉行内布局组与 fitter，新增 `static float OptionRowHeight(string text)`（24pt 中文按"字宽 = 字号"估算行数，`44` 起步、单行 44、双行 72）并同时写 `minHeight/preferredHeight`（护栏 `N10`）。
3. 🟠 **每行重复引导词**：程序把契约 §5.0 冻结的 `Event.OptionLead`（`批示`）当成了**每行前缀**（`t.text = UICopy.Event.OptionLead + "：" + opt.text`），而它实际是选项区**上方**的 18px 小标（同文件 `optLead`）→ 屏幕上出现"批示"小标 + 两行"批示：…"。**修复**：行文本回归 `opt.text`，引导词只由上方小标承担（护栏 `N10` 的 `noPrefix`）。

门禁（修复后）：编译 **0 error / 11 warning**；`uipolish-check.ps1` **41 passed / 0 failed**；`visualpass-check.ps1` **34 passed / 0 failed**。

> 复现口径：这三条都属"**静态断言覆盖不到、必须实机看**"的类型（`N9`/`N10` 已在事后补上护栏）。`Assets/Event/EventManager.cs` 属工程 scope，本次为 Lead 直改热修，已在契约 §15 追加记录。
